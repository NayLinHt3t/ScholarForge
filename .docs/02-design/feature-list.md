# Feature List — ScholarForge

Consolidated from the [backlog](../01-requirements/backlog.md), grouped by area. "Priority" mirrors the backlog's MoSCoW ratings.

> Scope note: content generated by the app (Section 6) is a read-only idea/outline scaffold, not a finished paper — there is no in-app text editor. All library/outline data is scoped per **project** (Section 2), not one account-wide pile.

## 1. Accounts
- Email/password signup and login (no third-party identity provider) — **Must**
- Persistent session (signed httponly cookie, ~30 day expiry) — **Must**
- Logout (session invalidation) — **Must**
- Per-account data isolation (projects scoped to the logged-in user) — **Must**

## 2. Projects (Workspaces)
- Create a named project — **Must**
- Open a project; every subsequent search/save/generate/list action scopes to it — **Must**
- Delete a project, cascading to its saved resources and outlines, with confirmation — **Must**
- Switch between projects from a single project list/switcher — **Should**

## 3. Idea-Based Search (within a project)
- Free-text idea input (not title/DOI-only) — **Must**
- Candidate retrieval from Semantic Scholar + CrossRef — **Must**
- Semantic re-ranking via local embedding similarity — **Must**
- Result cards with title/authors/year/venue/abstract excerpt — **Must**
- Graceful empty/low-relevance state — **Should**
- (v2) LLM-based query rewriting for better recall — **Could**

## 4. Personal Library (per project)
- Save a search result to the current project's library — **Must**
- Duplicate detection scoped to the current project (by DOI/arXiv ID) — **Must**
- View/remove saved resources within the current project only — **Must**
- Library persistence across sessions, per project — **Must**

## 5. Citations
- APA, MLA, and **IEEE** formatting by default — **Must**
- Chicago formatting — **Should**
- BibTeX export (single entry + whole library) — **Should**
- Graceful handling of missing fields (author/year) — **Should**

**IEEE citation format spec** (`toIEEE(resource)`):
- In-text: bracketed number only, e.g. `[1]`, `[2]` — assigned by order of first citation in the document, not alphabetical.
- Reference list entry: `[N] A. B. Author, C. D. Coauthor, "Title of paper in sentence case," *Abbreviated Venue Name*, vol. X, no. Y, pp. ZZ–ZZ, Mon. Year.`
- For a preprint/arXiv source with no journal/volume: `[N] A. Author, "Title," *arXiv preprint arXiv:XXXX.XXXXX*, Year.`
- Missing fields are omitted cleanly (no "vol. undefined") rather than left blank.

## 6. Idea & Outline Generation — a scaffold, not a finished paper
- Section-by-section RAG generation from the current project's saved library — **Must**
- **Default structure follows IEEE paper conventions**: Title, Abstract, Index Terms, Roman-numeral sections (I. Introduction, II. Related Work, III. Proposed Methodology, IV. Expected Contribution) — **Must**
- Each section contains **bullet-point ideas/talking points + a short example starter passage**, not full polished prose — **Must**
- Citation-marker validation (no hallucinated sources) — **Must**
- Deterministic, code-generated bibliography (not LLM-authored) — **Must**
- Citation-style choice for the generated bibliography (APA/MLA/Chicago/IEEE, default IEEE) — **Should**
- Per-section regeneration (redo one section without discarding the rest) — **Should**
- Clear error state when the local AI engine (Ollama) is unreachable — **Must**

## 7. Outline Review & Export — no in-app editor
- Read-only rendering of the generated outline; **no rich-text editing surface** — **Must**
- Copy-to-clipboard per section and "copy all" — **Must**
- **"Download as PDF"** — renders the outline, clearly labeled as a draft/aid (title block, abstract, numbered IEEE sections with bullet ideas, IEEE-numbered references), single-column in v1 — **Must**
- Markdown/plain-text export (secondary, for continuing to write elsewhere) — **Should**
- Two-column IEEE conference-style PDF layout — **Could** (v2 stretch; single-column ships first)
- Multiple saved outlines per project — **Could**

## 8. Reliability
- Partial-result degradation if one external API fails — **Should**
- Friendly messaging on rate limits/network errors — **Could**

## 9. Compliance (cross-cutting, see [legal-requirements.md](../03-compliance/legal-requirements.md))
- Access/action logging retained ≥ 90 days, tied to account — **Must**
- Password hashing, data minimization, deletion support (including full project-delete cascade) — **Must**
- Recorded consent (who/what/when/how) at signup — **Should**
