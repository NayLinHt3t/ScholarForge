## Functional Requirements

| ID | As a… | I want to… | So that… | Priority | Acceptance Criteria | BL ref |
|----|-------|------------|----------|----------|---------------------|--------|
| COMP-FR-01 | system operator | the system to write an access-log entry for every network-facing request | I can demonstrate Computer Crime Act §26 compliance by producing a trace linking each action to an identifiable user | Must | A request-logging middleware records, for every HTTP request to any endpoint: timestamp (UTC), source IP address, authenticated user_id (or the string "unauthenticated" if no valid session), HTTP method, and request path; entries are written to a store separate from application data tables; no endpoint that handles user data is exempt from logging. | BL-27 |
| COMP-FR-02 | student | my personal data to be collected only for stated purposes, stored securely, and fully deletable on request | my PDPA privacy rights are upheld throughout the lifetime of my account | Must | Personal data fields (email, hashed password, session tokens, project names, bibliographic metadata) are collected only for account operation under contract necessity; passwords are stored as bcrypt hashes only (AUTH-NFR-01); all personal data is fully removable via the account deletion flow (AUTH-FR-05) with cascade across every application table; no new personal data field may be added to any schema migration without a documented legal basis in code comments or a data-processing record. | BL-28 |

## Non-Functional Requirements

| ID | Quality | Measure | Priority | BL ref |
|----|---------|---------|----------|--------|
| COMP-NFR-01 | Log retention | Access-log rows must not be deleted before they are at least 90 days old; a scheduled cleanup job may delete rows older than 90 days but must not update or delete individual rows at any other time (append-only semantics enforced at the application layer) | Must | BL-27 |
| COMP-NFR-02 | Log isolation | Access logs must be stored in a table or file separate from all application data tables; no application code path in normal operation may execute UPDATE or DELETE on individual access-log rows | Must | BL-27 |

## Legal / Compliance Requirements

| ID | Law | Obligation | Concrete requirement | Applies to |
|----|-----|------------|---------------------|------------|
| COMP-LR-01 | CCA §26 | Access-log content, retention, and integrity | Each log entry must contain: timestamp (UTC), source IP, user_id (or "unauthenticated"), HTTP method, request path; retained ≥ 90 days; append-only; stored separately from application data; may be a dedicated database table or an append-only log file | COMP-FR-01, COMP-NFR-01, COMP-NFR-02 |
| COMP-LR-02 | PDPA | Data minimisation, secure storage, and erasure | Collect only personal data necessary for account operation; store passwords as bcrypt hashes (AUTH-NFR-01); provide an end-to-end deletion path (AUTH-FR-05) removing all user data across every table; do not send personal data to a new external service without first verifying the action is within the consent/purpose scope already communicated to users | COMP-FR-02 |

### Legal watch items

- **COMP-LW-01** (PDPA): Breach notification — if personal data is compromised, the data controller must notify the regulator (and affected individuals for high-risk incidents) within the required statutory window. The access logs specified in COMP-FR-01 provide the evidence needed to determine which accounts were potentially affected. A documented incident-response procedure (who notifies, what timeline, which regulator) is required before real users onboard — this is an organisational requirement that cannot be satisfied by code alone. Flag to a human before the first real-user deployment.
